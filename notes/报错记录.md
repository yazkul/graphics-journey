# 报错记录

> 格式：**现象 / 原因 / 解决**。每条都要写，这是你以后最值钱的文件。

## 2026-10-18  VS Code 报 "检测到 #include 错误，请更新 includePath"

- **现象**：`#include <Eigen/Dense>` 下面有红波浪线，但 `make` 能编过
- **原因**：VS Code 的 C/C++ 插件和编译器是**两套独立配置**。插件用 `c_cpp_properties.json`，编译器用 `CMakeLists.txt`
- **解决**：在 `.vscode/c_cpp_properties.json` 的 `includePath` 加 `/opt/homebrew/include/eigen3`
- **教训**：**红波浪线 ≠ 代码错**。判断标准永远是终端里 `make` 有没有 `error:`

## 2026-10-18  OpenCV 头文件找不到（opencv4 路径不存在）

- **现象**：`ls /opt/homebrew/include/opencv4/opencv2/opencv.hpp` → No such file
- **原因**：Homebrew 装的是 **OpenCV 5.0**，目录名从 `opencv4` 变成了 `opencv5`，位置也不是 `/opt/homebrew/include`
- **排查命令**：`brew list opencv | grep "opencv.hpp"`
- **真实路径**：`/opt/homebrew/Cellar/opencv/5.0.0_11/include/opencv5/opencv2/opencv.hpp`
- **解决**：includePath 写 `/opt/homebrew/opt/opencv/include/opencv5`（用 `opt` 软链接，升级不失效）
- **教训**：**教程里的路径会过期，永远用命令查真身**

## 2026-10-18  cmake 报 "Could not find a package configuration file provided by OpenCV"

- **现象**：`find_package(OpenCV REQUIRED)` 失败
- **原因**：Homebrew 的 opencv 是 keg-only（没链接到 `/opt/homebrew/include`）
- **解决**：`cmake -DCMAKE_PREFIX_PATH=$(brew --prefix opencv) ..`
- **教训**：keg-only 的包必须告诉 CMake 它装在哪

## 2026-10-18  HW1 跑出来是一条横线

- **现象**：`./Rasterizer -r 30 output.png` 只画出一条白线
- **原因**：**这不是 bug**。三个矩阵还是单位阵，三角形被压扁了
- **解决**：写完 `get_model_matrix` / `get_view_matrix` / `get_projection_matrix` 就正常了
- **教训**：先分清"环境错"和"还没写"

## 2026-10-18  macOS 没有 timeout 命令

- **现象**：`timeout 60 ./Rasterizer` → command not found
- **原因**：`timeout` 是 GNU coreutils 的，macOS 自带没有
- **解决**：`brew install coreutils` 后用 `gtimeout`，或者用 `perl -e 'alarm 60; exec @ARGV' 命令`
